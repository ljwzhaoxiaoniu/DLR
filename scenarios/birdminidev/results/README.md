# Batch-run results (the results docs)

English | [中文](README.zh.md)

> This directory archives `birdminidev`'s **run results** — structured like the old results: **traceable raw + summaries + per-question detail**, updated as runs happen.
> Produced by: `run_batch.sh` (parallel run) → `tsm grade` (verdicts & summary) → `tsm stats` (aggregate stats + the [DETAIL.md](../DETAIL.md) ledger + syncing the scenario README's blocks).
> **Historical note**: this manual chain is the 500-question ledger's historical workflow; the current exam system is `dsh-tsm-eval` (`dsh-eval all` — run + score + report in one command, see its README) — it reproduces this chain field for field and adds the report layer.

## Structure

```
results/
├── README.md            # ← this doc (how it is produced, read, updated)
├── stats.svg            # the aggregate chart (generated by `tsm stats`; the scenario README §5 embeds the same file)
├── STATS.md             # cross-round statistics, text form (per round / coverage / efficiency)
└── <run_id>/            # one round = one directory (e.g. 0924_1559_qids_1473_1480_1500)
    ├── questions.tsv    # the round's dispatch list (qid / db / question, taken from the dataset itself)
    ├── raw/             # ★ traceable: each question's dsh --json event stream (+ .err)
    │   └── 0924_1559_1473_dlr.ndjson
    ├── questions.csv    # per-question machine-readable detail: verdict / ruling / accuracy / answer / expected / steps / tool calls / tokens / log path / session id
    └── summary.md       # round summary: per database × verdict + non-PASS detail
```

The matching **session logs** live under `DSH-based Agent Service/.dsh-home/sessions/<cwd-slug>/<session>/session.v4.jsonl.zstd` (`<session>` is the CSV's `session` column — replayable forensics; multi-frame zstd, decoder `DSH-based Agent Service/scripts/decode_session_log.cjs`).

## Judging calibers (`tsm grade` v1)

- **Expected value** = the question's own **gold SQL** executed on that database's SQLite (**dataset-native, never corrected**)
- **Comparison**: numbers through tolerance tiers `[1e-9, 1e-6, 1e-4, 1e-3]`; text/lists by normalized containment
- **Verdicts**: `PASS` ｜ `FAIL` ｜ `UNCERTAIN` (no comparable value could be extracted) ｜ `GOLD_ERR` (gold itself failed to execute)
- ⚠ v1 is **rule-based**: `UNCERTAIN` / `GOLD_ERR` go to the human/arbitration list, **never auto-scored**

## Ruling calibers (**main caliber**: with the SOP in effect, rulings follow it; the verdict becomes the archive)

| Ruling | Meaning |
|---|---|
| ✅ correct | Matches gold (i.e. PASS) |
| 🔁 overturned | Does not match gold, but **the answer follows the SOP's ruling caliber** → counted correct, **marked and counted separately, never merged into ✅ correct** |
| ❌ wrong | Judged wrong (including "the SOP gave a caliber and the agent's answer violates it") |
| ⚠️ pending | Unarbitrated / no comparable value could be extracted |

- Derivation: the `ruling` column of `questions.csv`; `tsm grade` looks up the **`Type: dataset issue` section whose title matches the question** in `sources/sop.md` — a `> **Expected**: <value>` in the section is compared against directly; a section whose caliber is "the answer is empty" checks that the agent says so too.
- **The verdict column is never touched** (it still compares against gold, dataset-native); **an overturn never counts as PASS**: README / DETAIL / STATS / `stats.svg` all keep it in its own column.
- The calibers come from the knowledge layer (the SOP) — consistent with "ruling calibers follow the knowledge layer"; changing a caliber means changing the SOP, never the statistics code.

## Updating (kept live while running)

A problem met while running — **dataset issue / modeling conflict / hard question / other** → add a section (and the tag) in `../sources/sop.md`
(calibers: [docs/04-application.md](../../../docs/04-application.md) §2) → `tsm build sop` to rebuild the retrieval index → effective on the next round.

## How a round is run

```bash
# 1) run in parallel (several dsh processes; start the backend first)
bash "DSH-based Agent Service/scripts/run_batch.sh" --all --jobs 4
# 2) verdicts & summary (one round; produces questions.csv / summary.md)
cd "TSM Core Service" && tsm grade --run "../scenarios/birdminidev/results/<run_id>"
# 3) aggregate stats + detail (cross-round; recomputes stats.svg / STATS.md / DETAIL.md and syncs the scenario README §1/§5)
tsm stats
```

## Caliber reminders

- **The main caliber = rulings** (per the SOP): ✅ correct / 🔁 overturned / ❌ wrong / ⚠️ pending — **the dataset's problems are not charged to the application**; the verdict (raw gold comparison) is kept as archive only.
- **Distributions count occurrences** (reruns count again); **coverage counts distinct questions** (how many questions were ever run — independent of verdict/ruling); both come from `tsm stats`.
- `UNCERTAIN` / `GOLD_ERR` are **pending arbitration**, never auto-wrong; raw and verdicts are archived (the `questions.csv` is recomputed by `tsm grade` from rules — do not rerun grade before human arbitration).
