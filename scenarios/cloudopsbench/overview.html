TSM 建模实例化 · 一道题看三级语义

以 boutique/admission/5（题面「Service Availability Disruption.」）为例：L3 定走法 → L2 定入口链与读法 → L1 给出对象 / 面 / 按锚 read 模板 → agent 沿链经基准工具实查 → 证据链闭合。

L3 · SOP业务逻辑级 · 题面措辞逐字命中一节 → 定走法
  • 检索 = 节标题与题面逐字比对（命中即「复述本题」，零误配；下方句子全部是实测陷阱产物、逐条有复跑背书）。
  • 「If the wording names no service, the inventory listing is the legitimate entry: the moment it names the outlier, the victim's own signal leads — its endpoints listing, or a connectivity probe on the port its Service declares, or its caller-side error log — ahead of its workload state, the event surface, and any config read.」
  • 「Pod never created → admission side: the victim's own signal comes first — its endpoints listing, or a connectivity probe on its declared port (not a guessed one), or its caller's error log; if you batch, the signal leads the batch. Then the event names the referenced object; template reference (GetAppYAML) + the referenced object's own listing.」
L2 · CONSENSUS领域共识 · 入口链与读法 → 定怎么读
  • 「Symptom wording → entry chain — 'Service Availability Disruption.' uses the SAME reachability chain (it is overloaded across scheduling / startup / admission stages): walk caller logs → endpoints → pods; when the pods surface shows the pod never became ready, read its phase and events (FailedScheduling / FailedCreate / FailedMount / image-pull / probe) and follow that mechanism to the matching object surface. Discriminate on the chain, not on the wording.」
  • 锚 chain:reachability · 来源 case：boutique/scheduling/1 · startup/1 · admission/1
L1 · DLR数据源级 · LE ◀ PE ◀ ARCS → 实体 / 观测面 / 按锚读法模板 
构图：LE（业务对象） ◀─1:N 容器── PE（语境视图） ◀─ARCS（A 锚 · R 行空间 · C 列 · S 补注）── 快照资源
       A 锚 = 取数 WHERE 键（剪枝）；R: null = 行对行；S = 面的读法模板

                            → upstream = checkoutservice（症状的入口）

  PE  deployment 面   ARCS  A: 1:1 · key=app_label        R: null
