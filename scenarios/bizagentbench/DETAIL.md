**指标口径**（与上游 `README.md` 一致）：

| 指标 | 含义 |
|---|---|
| G · Goal | 请求的业务结果与允许的终止条件（目标类 check） |
| P · Process | 业务操作的执行要求（审批、顺序、时限、单次完成等） |
| F · Protection | 受保护对象、账本完整性、禁止性副作用（不重复付款、不越权等） |
| Strict | G ∧ P ∧ F 全过（本题表一“strict”列） |
| IF · Intermediate failure | `1 − P∧F`：过程或保护要求失败的比例（与 G 是否达成无关）。业务结果可能对，但审批/顺序/时限/账本/授权违规——合规质量指标；strict 高而 IF 不低，说明“结果对、过程不干净” |

## 二、优化过程（有价值的记录）

### 2.1 两条 L3 手段（实测翻盘）

**Wrong turn（负向 few-shot）**——规则已在节里、agent 仍走“看起来合理”的岔路时，把实测到的那个错误动作补一行。实测翻盘：

- 019 `34/35 → 35/35 strict`（不要“保险起见”重绑未升版 authority）
- 021 `29/30 → 30/30 strict`（结算顺序：员工先于卡单？以 due 分钟为准）
- 025 `28/29 → 29/29 strict`（courier/额度释放）
- 009 `41/42 → 42/42 strict`（marketplace 公式 + due-0 当刻付）
- 007 的 `joint.fee_and_reserve` 关闭（余 cargo/EUR 时机方差）

**Check before closing（收口）**——钉住关账时必须成立的业务不变量（不是 verifier 检查名）。实测翻盘：

- 037 / 038 / 042 / 044 / 045 / 046 → strict（6 题）
- 048 / 049 / 050 当轮未翻（多点/方差），049 后来由“通知绑定”补上

读法：**best 是同一 L1/L2 下真实跑出的最佳有效轮，不是稳定率**；论文的 3 轮均值只能部分压制噪声，接近名次不宜作强弱结论。

### 2.5 判定与冻结纪律

- **assisted 口径**：DLR 工具替代数据集的 `search_knowledge` / `read_document`；模拟器、记录/动作工具、verifier 不变，两档不混报。
- **每题一轮起步**：strict = stop；无 strict 且有新手段才复验；每题最多两遍；不买方差。
- **不作弊**：不写实例值/记录 ID/固定分钟，不许答案倒推，不改 gold/verifier。
- **freeze 只钉 L1/L2**；L3 按题拼接，每题锚定其运行时节的文本；改节后只复跑该题。
- **3 次经验上限**：没有明确优化空间就归档 best；无效/排除轮如实标注。
