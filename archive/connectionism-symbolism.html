工程化
三种范式

同一套数据，三种建模哲学

ER 范式

数据库建模标准基线

经典实体-关系模型：BizEntity 是业务实体，BizAttribute 是属性， BizRelation 是实体间关联。Agent 通过实体→属性→关系的层级探索来定位数据。

核心模型：BizEntity / BizAttribute / BizRelation
MCP 工具：10 + execute_sql

★ DLR 范式

原创 LE-PE 双层解耦模型

逻辑实体（LE）承载业务概念及其自然语言描述， 物理实体（PE）锚定真实表列，通过 ARCS 挂在 LE 下。 PAS 在 LE 之间建立带方向的谓词桥， 碎表/关联表作为 PE 聚合到 LE，Agent 只看业务对象。

核心模型：LE / PE / PAS / ARCS
MCP 工具：20 + execute_sql

RDF 范式

W3C R2RML 标准基线

W3C 标准 R2RML 映射：TriplesMap 将表映射为三元组， SPARQL 查询语义。标准完备但扁平 triple 模型无属性归属， JOIN 通过 joinCondition 显式列名表达。

核心模型：rr:TriplesMap + rdflib SPARQL
MCP 工具：5 + execute_sql

DLR 机制

LE-PE 双层解耦：ARCS 纵向锚定 + PAS 横向路由

PE: Transactiontransactions_1k 表

ARCS：LE ↔ PE 纵向锚定

ARCS（Anchor-Row-Column-Semantic）将物理实体锚定到逻辑实体。 一个 LE 可聚合多个 PE——碎表对 Agent 透明，Agent 看到的是一棵完整的业务实体树。 A=锚定键、R=行过滤、C=列映射、S=语义补注。

PAS：LE ↔ LE 横向路由

PAS（Predicate-Attribute-Semantic）是逻辑实体之间的语义路由。 带方向的谓词桥（如 Customer generates Consumption）， Agent 沿 PAS 在业务概念之间导航，如同在概念图上行走。

public / private 属性分层

public：业务核心度量列，Agent 在 LE 层直接可见
private：内部 ID、技术字段，留在 PE 层，避免噪音干扰。

🎯 LE-PE 解耦的业务意义

DLR 将建模拆为两层：业务人员定义 LE 和关键 PE 属性， IT 人员一次性完成 PE→物理表的 ARCS 锚定。此后建模维护完全在概念层，不碰底层表结构。
vs ER：建模即定义物理实体和关系，业务人员被迫理解表结构——本质是 IT 视角
vs RDF：需专业知识，对业务人员、IT人员均不友好

案例分析

RDF 为什么输——两个典型案例

q11 · california_schools 列歧义：短名撞车

"Please list the codes of the schools with total enrollment over 500."

schools 表 (17K行 · 49列)
CDSCode, School, District, County...
❌ 没有 Enrollment
frpm 表 (10K行 · 29列)
CDSCode, School Code, Enrollment (K-12)...
✅ Enrollment 在这里

陷阱：正确答案是 schools.CDSCode，但 RDF 扁平 triple 中 frpm."School Code" 字面更匹配 "codes" → Agent 被列名吸走选错列。 ER 有实体-属性归属：Agent 知道 "学校编码" 来自 schools 实体而非 frpm 的属性。
结果：ER PASS | DLR PASS | RDF INCORRECT

q1529 · debit_card_specializing 扁平陷阱：被无关表吸走

"How much spent by customer '38508' at gas stations? How much spent in January 2012?"

transactions_1k (1K行 · 9列)
Date, Amount, Price, CustomerID...
⚠️ 交易流水样本，非全集
yearmonth (383K行 · 3列)
CustomerID, Date, Consumption
✅ 月度消费全集

陷阱：两个子问题分属两张表——"加油站花费"→ transactions_1k，"一月消费"→ yearmonth。 RDF 扁平 triple 中所有字段权重相等，Agent 被 transactions_1k 的 Date/Amount 吸走， 忽略 yearmonth.Consumption。ER 有实体层级区分表功能，Agent 分别查询。
结果：ER PASS | DLR PASS | RDF INCORRECT

共同根因：RDF 扁平 triple 模型 无属性归属——所有列/表在三元组海洋中视觉权重相等， Agent 无法区分哪个字段属于哪个实体、哪个表是关键、哪个是噪声。
ER/DLR 的实体-属性层级结构提供了 "谁属于谁"的架构信号，引导 Agent 做出正确选择。
